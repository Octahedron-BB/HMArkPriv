# HMArkPriv 跨应用调用协议

> 让其他鸿蒙 App 调用 HMArkPriv 执行特权 shell 命令（类似 Android 的 Shizuku）。
> 提供两种方式，可任选其一或组合使用。
> 日期：2026-11-04 ｜ 适用版本：HMArkPriv v1.x（HarmonyOS NEXT 7.0+）

---

## 一、先了解前提

### 1.1 为什么鸿蒙没有 Shizuku 那样的绑定式服务

Shizuku 依赖 Android 的 `bindService` + AIDL，本质是系统级 Binder 服务。
鸿蒙上逐一核实过：

| 组件 | 能否做无界面跨应用服务 |
|------|---------------------|
| `ServiceExtensionAbility` | ❌ 不在 API 26 导出列表 |
| `AppServiceExtensionAbility` | ❌ 存在但**仅 2-in-1 设备 + 需企业 ACL 权限** |
| `ActionExtensionAbility` / `ShareExtensionAbility` | ❌ 都是 UI 扩展，会弹界面 |

**结论**：普通个人开发者做不了"其他 App 无感绑定我的后台服务"。
所以我们提供两条现实路径。

### 1.2 使用前必须完成的三件事

1. **部署 daemon**（用户一次性操作，需要电脑 + hdc）
   ```bash
   hdc file send core/daemon.sh /data/local/tmp/hmpriv/daemon.sh
   hdc shell "nohup sh /data/local/tmp/hmpriv/daemon.sh >/dev/null 2>&1 &"
   ```

2. **用户打开过 HMArkPriv App 并授权一次文件夹访问**
   （picker 授权，通过 `fileShare.persistPermission` 持久化，之后无需重复）

3. **（仅方式 C+）创建队列槽位**
   ```bash
   bash scripts/setup-queue.sh 16
   ```

## 二、方式 A：Want + startAbilityForResult

### 2.1 特点

| 维度 | 说明 |
|------|------|
| 是否需要文件权限 | ❌ 不需要 |
| 是否拉起界面 | ✅ **会拉起 HMArkPriv 界面并闪现一次** |
| 能否同步拿结果 | ✅ 能 |
| 并发 | 天然串行（每次一个 Ability 实例） |
| 适合场景 | 低频调用、用户主动触发的操作 |

> **界面闪现是方案 A 的固有限制**，源于鸿蒙只允许 UIAbility 组件对外暴露入口。
> 换个角度这也是好事 —— 敏感操作让用户看见，符合安全直觉。

### 2.2 请求格式

```typescript
const want: Want = {
  bundleName: 'com.octahedron.hmpriv',
  abilityName: 'EntryAbility',
  action: 'hmpriv.execute',        // 必须带这个 action，否则走普通启动
  parameters: {
    cmd: 'id',                     // 要执行的命令
  },
};
```

### 2.3 响应格式

`resultCode`：

| 值 | 含义 |
|----|------|
| 0 | 命令执行成功（退出码 0） |
| 1 | 命令执行失败（非 0 退出码，或 daemon 不可用） |
| 2 | 参数错误（缺 cmd 或超长） |

`want.parameters`：

| 字段 | 类型 | 说明 |
|------|------|------|
| `output` | string | 命令输出（stdout + stderr 合并） |
| `exitCode` | number | daemon 返回的退出码 |
| `durationMs` | number | 执行耗时 |
| `error` | string | 错误描述（仅失败时） |

### 2.4 示例代码

```typescript
import { common, Want } from '@kit.AbilityKit';

async function execByWant(ctx: common.UIAbilityContext, cmd: string): Promise<string> {
  const want: Want = {
    bundleName: 'com.octahedron.hmpriv',
    abilityName: 'EntryAbility',
    action: 'hmpriv.execute',
    parameters: { cmd },
  };

  const result = await ctx.startAbilityForResult(want);
  if (result.resultCode === 0) {
    return result.want?.parameters?.['output'] as string ?? '';
  }
  throw new Error(result.want?.parameters?.['error'] as string ?? 'exec failed');
}

// 调用
const out = await execByWant(this.context, 'id');
console.info(out);   // uid=2000(shell) gid=2000(shell) ...
```

## 三、方式 C+：共享文件队列（推荐）

### 3.1 特点

| 维度 | 说明 |
|------|------|
| 是否需要文件权限 | ✅ 需要 `READ_MEDIA` / `WRITE_MEDIA` |
| 是否拉起界面 | ❌ **完全后台，无感** |
| 能否同步拿结果 | ✅ 轮询读取 |
| 并发 | ✅ 支持（16 个槽位） |
| 依赖 HMArkPriv App 存活 | ❌ 不依赖（daemon 独立运行） |
| 适合场景 | 高频调用、后台任务、需要隐私 |

### 3.2 目录结构

```
Download/HMArkPriv/
├── req/                       # 请求队列
│   ├── slot0.req   … slot15.req
├── res/                       # 结果队列
│   ├── slot0.res   … slot15.res
├── cmd.req                    # 协议 1（兼容旧客户端）
├── cmd.res
└── status.json                # daemon 心跳
```

**为什么是固定槽位而不是动态文件**：
daemon 以 `shell`（uid 2000）身份运行，在 hmdfs 目录下**无法创建新文件**
（SELinux 禁止 create，只能读写已存在文件）。
所以 `slotN.req` / `slotN.res` 必须用 `hdc` 预先创建好（`scripts/setup-queue.sh`）。

### 3.3 协议

**请求**：把命令写入 `req/slotN.req`（纯文本，一行）

```
id
```

**响应**：读 `res/slotN.res`，格式：

```
RC:0
TIME:2026-11-04 15:56:02
uid=2000(shell) gid=2000(shell) groups=2000(shell),1006(file_manager),... context=u:r:sh:s0
```

第一行 `RC:<退出码>`，第二行 `TIME:<时间>`，之后是命令输出。

**注意**：
- daemon 处理完会**清空** `req/slotN.req`，你可以立刻写入下一条
- 读完结果后请**自行清空** `res/slotN.res`，否则下次会读到旧结果
- 写请求后务必 `fsync`，否则 daemon 可能读到空内容

### 3.4 示例代码

```typescript
import { fileIo } from '@kit.CoreFileKit';

const BUS = '/storage/Users/currentUser/Download/HMArkPriv';

async function execByQueue(cmd: string, timeoutMs = 25000): Promise<string> {
  const slot = 0;                              // 生产环境请做槽位分配
  const reqPath = `${BUS}/req/slot${slot}.req`;
  const resPath = `${BUS}/res/slot${slot}.res`;

  // 1. 清空上次结果
  const f1 = fileIo.openSync(resPath, 0o2 | 0o1000);   // READ_WRITE | TRUNC
  fileIo.closeSync(f1);

  // 2. 写请求（必须 fsync）
  const f2 = fileIo.openSync(reqPath, 0o2 | 0o1000);
  fileIo.writeSync(f2.fd, `${cmd}\n`);
  fileIo.fsyncSync(f2.fd);
  fileIo.closeSync(f2);

  // 3. 轮询结果
  const deadline = Date.now() + timeoutMs;
  while (Date.now() < deadline) {
    await new Promise<void>(r => setTimeout(r, 50));
    let text = '';
    try {
      text = fileIo.readTextSync(resPath);
    } catch { continue; }
    if (text.startsWith('RC:')) {
      const lines = text.split('\n');
      const rc = parseInt(lines[0].match(/RC:(-?\d+)/)?.[1] ?? '-1');
      const output = lines.slice(2).join('\n').trim();
      // 清空结果
      const f3 = fileIo.openSync(resPath, 0o2 | 0o1000);
      fileIo.closeSync(f3);
      if (rc !== 0) throw new Error(`exit ${rc}: ${output}`);
      return output;
    }
  }
  throw new Error('timeout');
}
```

### 3.5 需要声明的权限

```json5
// module.json5
"requestPermissions": [
  { "name": "ohos.permission.READ_MEDIA" },
  { "name": "ohos.permission.WRITE_MEDIA" }
]
```

> 首次运行若读不到总线文件，说明用户还没在 HMArkPriv App 里授权过。
> 引导用户打开 HMArkPriv → 点「授权」→ 选择 `Download/HMArkPriv` 目录。

## 四、两种方式对比

| | 方式 A（Want） | 方式 C+（队列） |
|---|---|---|
| 界面 | 会闪现 | 无感 |
| 权限要求 | 无 | 文件读写 |
| 依赖 App 存活 | 每次拉起 | 不依赖 |
| 并发 | 串行 | 16 槽位 |
| 单次延迟 | ~300-500ms（含启动开销） | ~60-100ms（轮询开销） |
| 数据量 | 受 Want 参数限制 | 无限制 |
| 实现复杂度 | 低 | 中 |

**建议**：优先用 C+；在用户没有授予文件权限、或者只是想低频试一下时用 A。

## 五、安全提示

⚠️ **这条通道等价于给调用方 root-ish 权限**（UID 2000 shell）。
任何能写总线目录的 App 都能执行任意 shell 命令，包括：

- 读取/删除其他 App 的数据目录
- 修改系统设置
- 模拟用户输入（点击、滑动、按键）
- 强制停止任意应用

**建议调用方**：
1. 不要把用户输入直接拼进命令（命令注入风险），做白名单或严格转义
2. 在 App 内明确告知用户你将执行什么命令（方式 A 的界面闪现天然满足）
3. 不要滥用 `uinput` 模拟点击做自动化刷量

**建议 HMArkPriv 用户**：
1. 只授权信任的 App 使用这条通道
2. 定期检查 daemon 是否在运行（不需要时 `kill` 掉 daemon 即可断开所有调用）

## 六、故障排查

| 现象 | 原因 | 解决 |
|------|------|------|
| 方式 A 报 `startAbilityForResult failed` | HMArkPriv 未安装 | 先安装 App |
| 方式 A 界面闪一下就消失，拿不到结果 | resultCode=1，看 error 字段 | 检查 daemon 是否在跑 |
| 方式 C+ 报"槽位文件不存在" | 未运行 setup-queue.sh | 在电脑上执行 `bash scripts/setup-queue.sh 16` |
| 方式 C+ 一直超时 | daemon 挂了，或命令被 timeout 终止 | 检查 `status.json`；重启 daemon |
| 方式 C+ 读到旧结果 | 没清空 `res/slotN.res` | 每条请求前先清空 |
| 所有槽位都占用 | 上一个命令卡住了 | 检查是否有 `hidumper -c` 之类的死命令 |

> ⚠️ **绝对不要通过这条通道执行 `hidumper -c` 或 `hidumper --mem`（不带管道）** ——
> 这两个命令会阻塞在内核态 Binder 调用，daemon 会永久挂起，只能重启。

## 七、附：SDK

现成的封装在 [`arkui-app/sdk/HmprivClient.ets`](../arkui-app/sdk/HmprivClient.ets)，
直接拷进你的工程即可：

```typescript
import { HmprivClient } from './utils/HmprivClient';

// 方式 C+（推荐，无界面）
const r1 = await HmprivClient.execByQueue('id');
console.info(r1.output);

// 方式 A（会拉起界面）
const r2 = await HmprivClient.execByWant(this.context, 'id');
console.info(r2.output);

// 便捷方法
await HmprivClient.wakeup();
await HmprivClient.tap(500, 1200);
await HmprivClient.keyPress(2);           // Back
await HmprivClient.forceStop('com.example.app');

// 健康检查
if (!HmprivClient.isDaemonReady()) {
  console.warn('daemon 未运行，请先部署');
}
```
